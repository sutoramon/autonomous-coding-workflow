# Project Onboarding

Read [core policy](../../WORKFLOW.md), [risk profiles](../../docs/RISK-PROFILES.md) and [onboarding procedure](../../procedures/01-onboarding.md). Follow the procedure appropriate to the project stage.

## Use when
A new application is proposed, requirements or architecture materially change, or an existing project explicitly adopts ACW. Do not repeat onboarding before an ordinary bug fix.

## Responsibilities
Define who benefits and how success is observed. Compare plausible options and document meaningful trade-offs. Create or reconcile project configuration, the actual repository, tool requirements, task acceptance criteria and reproducible verification. Keep production and tests isolated. Record consequential unresolved decisions; do not invent authorization or falsely claim installation.

## Exit
The project has an identifiable source baseline, acceptance behavior, a reviewed risk classification, actual project-specific checks, and a first executable task. For adoption, preserve existing rules and working changes.
